### 1. Блокирующая ошибка

`build-ci-image.yml:159` (до правки):

```yaml
echo "KERNEL_VERSION=${{ inputs.width_kernel || KERNEL_VERSION=false }}" >> "$GITHUB_ENV"
```

`KERNEL_VERSION=false` — не литерал, не контекст и не число, поэтому парсер выражений
падал с `Unexpected symbol: '=false'`. Владелец успел добавить такую же конструкцию
для `BASE_PKGS` (`:160`) и невалидный `${{ env }}` в `build-args` (`:170`).

Шаг удалён: `Dockerfile.ci` сравнивает `WIDTH_KERNEL`/`WIDTH_BASE_PACKAGES` с пустой
строкой и `false`, поэтому значения передаются напрямую через `build-args`.

### 3. `Dockerfile.ci`

- `:18-20` — `ARG WIDTH_KERNEL` не использовался: ставился `kernel-headers-$(uname -r)`
  от ядра runner-а. Теперь `kernel-headers-${WIDTH_KERNEL}` / `kernel-devel-${WIDTH_KERNEL}`,
  пустая строка и `false` — пропуск (раньше `!= "false"` пропускал пустое значение в `dnf`).
- `:22` — `centos-stream-$-$(arch)` (сломано после правки владельца) и неопределённый
  `os_ver`. Теперь `os_ver` из `rpm -E '%{rhel}'` с проверкой на число и fallback `10`,
  arch из `uname -m`.
- `:28-30` — `WIDTH_BASE_PACKAGES != "false"` не защищал от пустой строки
  (`dnf -y install` без аргументов). Добавлено `-n`.
- `:2` — мёртвый `ARG BASE_PKGS` с теми же неверными именами удалён; список перенесён
  в дефолт `ARG WIDTH_BASE_PACKAGES`.
- Комментарий `# shellcheck disable=SC2086` убран из `RUN`-продолжения: строка внутри
  `RUN ... \` может быть склеена в шелл-комментарий и «съесть» остаток инструкции.
