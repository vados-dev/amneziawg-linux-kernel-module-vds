## Тема: DKMS-сборка падает на kernel 6.12.0-273.el10 — анализ лога и upstream

### 1. Анализ лога (/var/lib/dkms/amneziawg/3.1.20260812/build/make.log)

5 ошибок + 2 предупреждения из-за повторных определений в `src/compat/compat.h` на ядре 6.12.0-273.el10.x86_64:

| # | Символ | Где в compat.h (лог) | Где в ядре | Тип конфликта |
|---|--------|----------------------|------------|----------------|
| 1 | `timer_container_of` | :1300 | `linux/timer.h:132` | warning redefined |
| 2 | `struct sockaddr_inet` | :1305 | `linux/in6.h:22` | error redefinition |
| 3 | `netif_threaded_enable` | :1314 (static) | `linux/netdevice.h:595` (non-static) | error static/non-static |
| 4 | `struct rtnl_newlink_params` | :1328 | `net/rtnetlink.h:81` | error redefinition |
| 5 | `rtnl_newlink_link_net` | :1335 | `net/rtnetlink.h:93` | error conflicting types |

**Причина**: ядро EL10 сообщает версию 6.12, но backport'ит API из 6.15/6.16/6.17
(`timer_container_of` — 6.16, `sockaddr_inet`/`netif_threaded_enable` — 6.17,
`rtnl_newlink_params` — 6.15). Guards по `LINUX_VERSION_CODE` на таких ядрах не работают.

### 2. Проверка upstream-веток (amnezia-vpn/amneziawg-linux-kernel-module)

Актуальные ветки (через GitHub API): `master` (4569c4c), `fix/compat-ubuntu` (2a037dc),
`build/newer-ubuntu` (826e962), `feature/awg4` (133e732). Ветки `main` не существует —
upstream использует `master`.

**master**: все 5 символов обёрнуты в guards по версии ядра:
- `timer_container_of` — `#if LINUX_VERSION_CODE < KERNEL_VERSION(6, 16, 0)`
- `sockaddr_inet`, `netif_threaded_enable` — `< KERNEL_VERSION(6, 17, 0)`
- `rtnl_newlink_params`, `rtnl_newlink_link_net` — `< KERNEL_VERSION(6, 15, 0)`

Для vanilla-ядер этого достаточно, но для EL10/Ubuntu backport-ядер — нет.
`ISRHEL10` upstream НЕ определяет (только ISRHEL7/8/9).

**fix/compat-ubuntu**: идентичен master, отличается только одним блоком —
guard на `setup_udp_tunnel_sock` для Ubuntu ABI >= 38 с ядром >= 7.0:
```c
#if !(defined(UTS_UBUNTU_RELEASE_ABI) && LINUX_VERSION_CODE >= KERNEL_VERSION(7, 0, 0) && UTS_UBUNTU_RELEASE_ABI >= 38)
#define setup_udp_tunnel_sock(net, sk, sock_cfg) setup_udp_tunnel_sock(net, sk->sk_socket, sock_cfg)
#endif
```
Решения для EL10 backports в upstream НЕТ — задача наша, локальная.

### 3. Состояние локального src/compat/compat.h (VDS)

Локальный файл УЖЕ содержит правки под EL10, которых нет в upstream:
- строки 21–27: определение `ISRHEL10` / `ISRHEL100` (RHEL_MINOR==0) / `ISRHEL101` (RHEL_MINOR==1)
- строки 1306, 1310, 1319, 1333: guards вида
  `#if LINUX_VERSION_CODE < KERNEL_VERSION(6, 16, 0) && !(defined(ISRHEL10) && !(defined(ISRHEL100) || defined(ISRHEL101)))`
  вокруг всех 5 конфликтующих блоков.

Смысл guard'а: на RHEL10 определения пропускаются ВСЕГДА, кроме 10.0/10.1
(предполагается, что в 10.0/10.1 backports этих API ещё нет).
